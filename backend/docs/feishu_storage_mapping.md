# 飞书共享 Base 字段映射与同步策略

共享服务只部署一套后端。团队用户登录 Agent 自己的账号体系，后端统一使用同一组飞书应用凭证连接同一个 Base；不要让每个用户在本地各跑一份进程并连接各自飞书。

## 环境变量

`.env` 中配置：

- `FEISHU_APP_ID`
- `FEISHU_APP_SECRET`
- `FEISHU_BASE_TOKEN`
- `FEISHU_TABLE_COMPANIES`
- `FEISHU_TABLE_USERS`
- `FEISHU_TABLE_PROJECTS`
- `FEISHU_TABLE_POSITIONS`
- `FEISHU_TABLE_PROMPTS`
- `FEISHU_TABLE_MATCH_RESULTS`
- `FEISHU_TABLE_TRACKING`
- `FEISHU_SYNC_ENABLED=true`
- `FEISHU_SYNC_STRICT=true`
- `APP_PUBLIC_URL=https://agent.innoreal.cn`

正式共享服务使用 `FEISHU_SYNC_STRICT=true`：飞书权限、字段或配置错误会阻断客户、岗位、提示词的写入，避免服务端 SQLite 缓存和飞书 Base 静默不一致。临时排障时可改为 `false`，后端会在飞书同步失败后短暂熔断并继续使用 SQLite 缓存。

## 同步策略

- 页面读取客户、岗位、项目、提示词时，只读取共享后端的服务端 SQLite。飞书 Base 是存储/备份目标，不参与每次页面渲染。
- 新增、编辑、删除客户/岗位/提示词时，后端先同步飞书，成功后再提交服务端 SQLite，并保存 `feishu_record_id`。
- `feishu_sync_jobs` 记录客户、岗位、提示词的同步状态；管理员可通过 `GET /api/feishu/sync-jobs` 查看失败队列，通过 `POST /api/feishu/sync-jobs/retry` 重试。
- 需要从飞书恢复或导入数据时，由管理员显式调用 `POST /api/feishu/pull?table=all`，或指定 `users/companies/positions/prompts/match_results/client_recommendations/tracking`。
- 项目管理仍以岗位表的 `is_project` 为准；重点项目会同步到飞书项目表，并用 `feishu_project_record_id` 防止重复创建。
- 非严格模式下飞书同步失败后会短暂熔断 60 秒，避免权限未开通时写入链路反复请求飞书。
- 匹配报告和进程管理当前仍以服务端 SQLite 缓存承载完整详情，但新增/更新时会同步写入 `FEISHU_TABLE_MATCH_RESULTS` 和 `FEISHU_TABLE_TRACKING`。如需飞书完全承载报告详情，需要在这两张表补完整 JSON/HTML/附件字段。

## 客户表字段

默认写入字段：

- `营业执照名称`（唯一工商主体名称）
- `公司名`（兼容旧表，按公司简称写入）
- `公司简称`（飞书客户表存在该字段时写入）
- `行业`
- `城市`
- `联系人`
- `合作状态`
- `客户备注`

读取兼容别名：

- 营业执照名称：`营业执照名称` / `工商注册名称`
- 公司简称：`公司简称` / `简称` / `品牌简称` / `公司名` / `客户名称` / `公司名称` / `客户名` / `客户`
- 城市：`城市` / `地区` / `客户地址`
- 行业：`行业` / `行业大类` / `客户行业`
- 外部联系人：`外部联系人` / `客户侧联系人` / `联系人`
- 状态：`状态` / `合作状态`
- 备注：`客户备注` / `备注` / `客户简介`

状态映射：

- App `开发中` → 飞书 `意向中`
- App `已签约` → 飞书 `合作中`
- App `历史客户` → 飞书 `已终止`

## 岗位表字段

默认写入字段：

- `岗位名称`
- `客户`
- `薪资范围`
- `城市`
- `招聘数量`
- `项目状态`
- `顾问`
- `硬性要求`
- `优先条件`

读取兼容别名：

- 岗位名称：`岗位名称` / `职位名称` / `项目名称`
- 客户：`客户` / `岗位公司` / `公司` / `公司名称` / `客户公司` / `所属客户`
- 城市：`城市` / `工作城市` / `工作地点`
- 薪资：`薪资` / `薪资范围`
- JD：`JD原文` / `岗位JD` / `岗位要求` / `职责要求` / `岗位职责` / `任职要求`

状态映射：

- 飞书 `待发布/招聘中` → App `active`
- 飞书 `已暂停/已关闭/已完成` → App `archived`

## 项目表字段

项目表是重点项目同步表，不作为第二套岗位数据源。

默认写入字段：

- `本地岗位ID`
- `项目名称`
- `客户`
- `城市`
- `薪资`
- `项目状态`
- `顾问`
- `项目描述`
- `招聘人数`

项目状态映射：

- App `未开始` → 飞书 `待启动`
- App `进行中` → 飞书 `进行中`
- App `已结束` → 飞书 `已完成`

## 提示词管理表字段

当前新表：`提示词管理`（`tblCT4rwod6nj1vw`）。同一张表通过 `层级` 字段分为三类，并配置三个视图：`通用提示词`、`客户提示词`、`岗位提示词`。

默认写入字段：

- `本地ID`
- `层级`
- `提示词名称`
- `提示词类型`
- `公司`
- `岗位`
- `提示词内容`
- `版本`
- `版本号`
- `是否生效`
- `状态`
- `更新人`

读取兼容别名：

- 层级：`层级` / `类型` / `提示词类型`
- 内容：`提示词内容` / `内容` / `prompt` / `Prompt`
- 公司：`公司` / `客户`
- 岗位：`岗位` / `项目` / `岗位名称` / `项目名称`

旧表 `提示词表` 已弃用，应删除。当前 Agent 写入目标由 `.env` 的 `FEISHU_TABLE_PROMPTS` 指向 `提示词管理`。
