# 参考示例（3 个短例，学习条件池、标签与依据）

以下示例只用于稳定输出格式与判断口径。实际判断必须以本次输入的 JD、公司提示词、岗位提示词和候选人简历为准，不要照搬示例条件。

## 示例 1：技术岗 / AI Agent 工程师

岗位要求：3 年以上算法经验；熟悉 Agent 架构；熟悉 RAG；有模型微调经验优先；本科及以上。

候选人摘要：2020 年起做 NLP 算法；近两年主导内部 Agent 平台，含记忆机制与工具编排；搭建过向量库知识问答；硕士；未提微调。

正确 rows：

| requirement | condition_type | label | note |
|---|---|---|---|
| 本科及以上学历 | blocker | 满足 | 候选人为硕士学历，满足学历门槛。 |
| 3 年以上算法经验 | seniority | 满足 | 2020 年至今持续从事 NLP 算法工作，年限满足。 |
| 熟悉 Agent 架构 | core | 满足 | 简历写到主导内部 Agent 平台，包含记忆机制与工具编排。 |
| 熟悉 RAG | relevance | 满足 | 简历提到搭建基于向量库的知识问答系统。 |
| 有模型微调经验 | preference | 待确认 | 简历未提微调或等价模型训练经历，需要顾问确认。 |

## 示例 2：产品/运营岗 / 增长运营

岗位要求：有用户增长或活动运营经验；能看数据并复盘；有内容社区经验优先；北京到岗；不接受纯行政背景。

候选人摘要：做过校园社群活动和公众号内容；负责活动报名、社群维护、基础数据统计；期望城市北京；未体现完整用户增长策略；曾做 1 年行政助理。

正确 rows：

| requirement | condition_type | label | note |
|---|---|---|---|
| 北京到岗 | blocker | 满足 | 候选人期望城市为北京。 |
| 有用户增长或活动运营经验 | core | 待确认 | 简历有活动和社群维护，但未明确用户增长目标、拉新转化或增长链路。 |
| 不接受纯行政背景 | blocker | 满足 | 候选人虽有行政经历，但也有社群活动和内容运营经历，不属于纯行政背景。 |
| 能看数据并复盘 | core | 满足 | 简历提到基础数据统计，可支持初级数据复盘，但深度需面谈确认。 |
| 有内容社区经验 | relevance | 满足 | 简历提到公众号内容和社群维护，和内容社区运营相关。 |

## 示例 3：销售/交付类 / 高净值房产管家

岗位要求：有高净值客户服务或大额销售经验；形象沟通好；能接受周末看房；有房产经验优先；薪资预期需匹配岗位预算。

候选人摘要：3 年奢侈品销售，维护 VIP 客户；客单价高，有复购维护经验；简历未写是否能周末工作；无房产行业经历；期望薪资 25K，岗位预算 18-22K。

正确 rows：

| requirement | condition_type | label | note |
|---|---|---|---|
| 有高净值客户服务或大额销售经验 | core | 满足 | 候选人有 3 年奢侈品销售和 VIP 客户维护经验，客单价较高。 |
| 形象沟通好 | risk | 待确认 | 简历未直接体现形象气质或现场沟通表现，需要顾问面谈确认。 |
| 能接受周末看房 | blocker | 待确认 | 简历未写工作时间接受度，需要顾问确认。 |
| 薪资预期匹配岗位预算 | blocker | 不满足 | 候选人期望 25K，高于岗位预算 18-22K。 |
| 有房产经验 | preference | 不满足 | 简历未体现房产销售、经纪或看房服务经历。 |

通用要点：
- 每条 rows 都必须包含 `requirement`、`condition_type`、`label`、`note`。
- `condition_type` 只能是 `blocker` / `core` / `relevance` / `seniority` / `preference` / `risk`。
- `label` 只能是 `满足`、`不满足`、`待确认`。
- 岗位主线一致且有强等价证据时可判 `满足`，但必须在 note 中说明等价关系。
- 简历没写清楚、但相近经历可部分支撑时判 `待确认`，不要直接判 `不满足`。
- 简历明确冲突或岗位主线明显不同才判 `不满足`。
- 不要输出分数；系统会按维度加权计算最终得分。
